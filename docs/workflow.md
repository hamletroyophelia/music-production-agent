# 音乐制作 Agent 工作流

本文件适用于扒谱、歌词与旋律对齐、Synthesizer V 人声、REAPER 编曲混音及修订。流程研究、说明和文档维护不自动启动歌曲或打开 DAW。用户本轮指示优先，历史工程和参数不作为新任务默认值。

## 1. 范围、角色与写入权

- 主控负责理解目标、协调与交付；如有规划者和执行者，规划者做一次范围/依赖规划，执行者在授权内连续制作。模型由使用者配置，不在技能中固定型号或推理档位。
- 已授权的可逆制作不重复请求确认。规划者只在真实阻塞、范围决策和交付清单收尾时介入，不为每批音符或每个旋钮增加复验门槛。
- 同一时刻只有一名 DAW/UI 写入者，覆盖 REAPER、SynthV、插件窗口、焦点、剪贴板和导出。工具不具备原生 UI 能力时，把具体操作交给当前写入者并交清写入权；不得并行改变工程或焦点。
- 先说清本次要解决的问题、会据此做什么。不会改变制作决策的检查不运行；成功回执已回答的问题不重复扫描。
- 只更新流程、回答问题或研究资料时，不创建歌曲任务、不打开 DAW。用户取消或未要求的主观验收，不作为继续制作的门槛。

## 2. 来源和工作副本

时间轴/结构、主旋律、歌词/音素和修订依据可以来自不同文件。逐项确认权威来源，不用一个文件代替所有事实：伴奏或工程规定结构和速度图；选定的 Voice MIDI、谱面或已接受 SVP 规定主旋律；含词 SVP 可提供歌词—音符关系；LRC 通常只提供歌词行级锚点。

含词工程不自动保证每句都正确；音符数量相同也不证明字音映射正确。旧 CSV、歌词行和历史“accepted”记录须与当前工程核对。原文件保留，在有清晰版本名的工作副本上修改。只在需要区分同名版本或追踪实际变更时计算哈希。

资料优先使用软件/声库厂商官方手册、官方教程、标准和原始论文。社区资料可以提供搜索线索，未被适用版本的官方资料或当前宿主确认的内容应标为候选，不能写成参数事实。

## 3. 制作顺序

1. **素材和版本：**确定伴奏、谱、MIDI、工程、歌词与参考录音的版本和职责；登记本轮范围和未决问题。
2. **旋律和时间轴：**沿用已确认 MIDI/工程；只在弱起、速度图、拍号、PPQ、缺段、八度或悬挂音有疑点时诊断。
3. **歌词与音符：**按段落和乐句建立关系。先迁移已有含词谱面的真实词音关系，再处理局部拆并、辅音和元音边界；不得按字数或字符数均分音符。方法见[对齐与视觉诊断](alignment-and-visual-diagnostics.md)。
4. **SynthV：**先对齐时间和歌词，再定绝对音域、声库/组级身份、模式、表情和音素。具体流程见[SV2 调参参考](synthv2-tuning.md)。
5. **编曲和混音：**先推子、声像与编配，再按具体遮蔽、齿音、动态、低频或空间问题选择处理。见[人声混音参考](vocal-mixing.md)。
6. **交付：**一次汇总实际文件、来源、规格和已知限制。阶段记录是追踪工具，不是用户确认门禁；修一段不触发全曲重做。

## 4. 对齐与视觉诊断

- 统一 tempo map、PPQ、拍号、弱起、小节原点、项目起点、媒体位置/源偏移/播放速率，以及 SV2 Group Reference 的局部时间和移调。四分音符拍数和秒数换算时按逐段速度图进行。
- 先用覆盖问题段开头、中间、结尾的稀疏锚点识别全局偏移、持续漂移或局部跳变，再放大有疑问的乐句。全局偏移才整体移动；随时间增长先查速度/播放率；局部跳变只修对应边界。
- 鼓适合定位节拍，不能推出主唱音高或歌词。音高要看旋律/MIDI/F0，歌词映射要看音节关系；和弦、bass 与 chroma 只是音乐上下文。
- 波形互相关仅适合足够相似的同源信号。跨演奏/配器可以用受限的旋律或 chroma 特征序列给出结构候选，不能自动拉伸来掩盖漏小节或错版本。
- 视觉诊断只选能改变下一步的局部波形、短时频谱、F0、起音、包络或相位证据。频谱不是试听，不能证明咬字清楚、音色自然或结果满意。详细边界见[对齐参考](alignment-and-visual-diagnostics.md)。

## 5. SynthV 写入规则

- 当前打开的 SynthV 工程是实时状态权威。写入前读取目标轨/Group；按需要核对 track 默认 Vocal 与所选 Note Group 的实际 Vocal、Voice Part 和完整 Vocal Modes。
- UI 可用时自行读取面板，不默认向用户索要截图。只有当前 UI 无法提供必要信息时才询问。
- 先查适用代际的官方文档，再按本机宿主/声库现场返回的范围、单位和模式名写值。不能从其他声库复制风格名、参数索引或归一化数值。
- `note.pitch`、Reference `pitchOffset`、`absolutePitch`、音高曲线和 Tone Shift 需分开记录；八度移调只用一种方法，避免对同一音符重复减 12。
- 每次写入使用刚读取的目标上下文和当前 API schema；遇到 stale/session-changed 后重新读取，不重发旧 payload。共享 Group 写入前确认会影响哪些 References。
- 只对本轮问题做一次定向检查；不因频谱/F0等客观量化就声称试听、自然或通过听感验收。

## 6. REAPER、混音和人声缺失排错

- 先读当前工程、目标轨/媒体、路由和实际插件实例；安装/扫描状态不等于许可证或已成功加载。调用的工具参数不熟时读当前工具 schema，不猜参数编号。
- 修改原件前建立工作副本；装载此前未用或发生过挂起的插件前保存。相同故障无新证据不重试，优先用可用稳定链完成授权工作。
- 用户反馈“无人声/人声过低”时，沿同一信号路径排查：先在同一时间窗和增益/处理阶段比较人声 stem 与其对应源，再查 item/take trim、`VOLENV2`、track fader、静音、FX 与路由，最后确认实际 master 路径中的人声贡献。不得用 pre-master 人声 stem 与 post-master 伴奏直接比较。
- 先修人声轨、item、包络或路由，不要先提高 Master；Master 增益会连伴奏一起抬高并减少峰值余量。
- 音量包络 `points_added` 仅说明 API 接受了点，不证明增益正确。当前接口的 `Volume` 约定应为线性增益；桥需按 `GetEnvelopeScalingMode` 内部转换并回执 raw/scaling 信息。若回执缺少这些信息，视为旧接口/旧服务，先确认当前 schema 和运行版本后再写；更新的 Lua 服务需真实重载。明确故障修复后，仅做一次受影响片段的定向确认。
- 离线改写正在打开的 `.rpp` 后，同路径再次 Open 不保证从磁盘重载；真正关闭旧工程，再从磁盘打开修改后的工程一次。原生正常保存不要求每次关开。
- 不因具体故障增加全曲测试、反复交锁或规划者审批门槛。继续遵守同一 DAW/UI 写入者。

## 7. 导出与交付边界

- 确认本轮实际的采样率、位深、声道、起点和时长；低规格导出再升采样不等于恢复精度。Stem 统一起点，按最后有效乐音和实际效果尾音决定结束位置。
- 文件路径、可读头信息和必要规格合并检查一次。它们不能证明听感或歌词可懂度。
- 只有处理峰值、相位、静音等具体问题，或用户合同要求时才测对应数值；针对明确反馈完成一次问题相关确认即可，不增加全套 QA。
- 若外部恢复处理与 `.rpp` 原生链不同，区分记录来源，不能称为该工程的可复现原生渲染。
- 最终说明只写实际改动、可播放文件、工程/stems 和真实限制。未试听必须明确写未试听；不虚构自然、清晰、完美或通过听感。
