# 人声混音参考

这是按问题选择处理的工作流，不是要求把所有插件串满的固定 preset。以下起始值属于制作经验，不是厂商参数或质量合格线；以当前信号、插件实例和用户目标为准。

## 1. 先建立可判断的平衡

先处理正确的主唱/和声来源、旋律音域和歌词时间，再做静态推子和声像。EQ、压缩、混响不会修复错歌词、错小节或八度错误。

```text
主唱干声（通常居中） → 需要时的修正EQ/动态 → Vocal Bus → Master
独立和声/叠唱       → 轻量均衡/动态 → 适度声像与效果发送
Bass / Kick / 乐器   → 各自平衡与总线 → Master
```

主唱宽度主要来自真实独立和声、叠唱及效果返回，保留清楚的居中主唱。若混合主唱与独立 stem 重复相加，先消除重复干声。Doubler 的同度副本不是三度/六度等独立和弦和声；同一源的延迟复制也不是独立表演。立体声扩展后仅在相关片段检查单声道折叠，不追求“越宽越好”。

## 2. 根据具体症状选处理

| 问题 | 先做什么 | 何时停止 |
| --- | --- | --- |
| 句间电平忽大忽小 | Clip gain 或推子自动化；若仍需要，再选一种主要压缩方案 | 保留主歌/副歌有意动态，不把每句压成等高 |
| 低频杂讯或非演唱低频 | 用当前可用 EQ 温和清除低频噪声，截止低于最低有效基频 | 不机械套用固定高通频率，尤其低音声部 |
| 个别词冲出、主体不稳 | 先做局部电平自动化，必要时轻压缩 | 不堆多个强压缩来追求等响 |
| 辅音被压没 | 减少快压缩/压缩量，检查原始辅音与音素长度 | 高频瞬态频谱只能辅助定位，不能证明可懂度 |
| 齿音、尖锐元音突出 | 先定位具体词，再用适当动态或局部高频控制 | 不为一两个词削平整条高频 |
| 人声在密集伴奏里消失 | 先推子/编配/音区，再考虑在人声或伴奏做小幅 EQ、短时 ducking | 频谱重叠只是遮蔽候选，不自动表示要挖空伴奏 |
| 人声太远 | 降低湿声返回或发送，视情况增加 pre-delay，保留干声主体 | 不靠不断提升高频补偿混响遮挡 |
| 想更厚/更靠前 | 小量饱和或一条平行处理，补偿输出增益再比较 | 没有明确改善就旁通，不把响度增加当作音色改善 |

开始建议：手动 EQ 小幅处理；ReaComp 可从 2:1–3:1、attack 10–30 ms、release 60–150 ms 作为经验起点，阈值依据实际包络设定。慢速低音句可能需要不同时间常数。所有数值均须按音源和实际实例调节，不是固定标准。

## 3. 和声、叠唱与空间

顺序通常为：独立和声内容 → 句子入口/退出和音量 → 左右分布 → 叠加/扩宽 → 混响。先确保和声本身有信号和合适音程，再拓宽。主唱干声保持可定位的中心；桥段、叠唱或效果返回可按编配展开。

- 先检查和声音符与和弦相符，不能用 delay 或 widening 掩盖字音/时间错位。
- 若确实用同度加厚或 widening，发送总线需避免多加一份原始干声。回送从低量开始；效果 timing 太大可能使发音含糊。
- 少量复制延迟有时可做立体声支撑，但不等于真实重唱；必须检查单声道折叠和梳状/相位感。Bass 的基音保持可辨，不以重混响掩盖低声部节奏。
- 短混响 pre-delay 可从 20–40 ms 作为经验起点。Delay 拍值可按 `60000 / BPM` 计算四分音符时长，再按八分/附点等细分。句尾自动化通常比全程高发送更可控。

官方资料可用作功能参考，不表示这些产品已安装、授权或适合当前工程：[REAPER Effects Guide](https://www.reaper.fm/guides/ReaEffectsGuide.pdf)、[Sonnox Voca 教程](https://toolbox.sonnox.com/Voca/How-to-use-Voca.html)、[Claro 教程](https://toolbox.sonnox.com/Claro/How%20to%20use%20Claro.html)、[VoxD Thicken 手册](https://toolbox.sonnox.com/VoxDoubler/Using%20VoxD%20Thicken.html)、[VoxD Widen 手册](https://toolbox.sonnox.com/VoxDoubler/Using%20VoxD%20Widen.html)、[VoxD FAQ](https://toolbox.sonnox.com/VoxDoubler/FAQ.html)、[Oxford Inflator 手册](https://dload.sonnoxplugins.com/pub/plugins/UserGuides/Oxford_Inflator_User_Guide.html)。

## 4. Bass、鼓和人声

先用编配与推子确定 kick 和 bass 的职责。只在同时出现的片段观察低频和中低频，不凭整曲平均谱决定所有 EQ。需要 kick 侧链时，使用正确辅助检测路由且不要把检测信号混入主输出；ducking 从轻量、短时开始，release 应在下一次节奏动作前恢复。

主唱降低音域后，重新检查与 bass/键盘的重叠，但保留主唱基频和 bass 可辨的谐波。拥挤时先减少键盘低音重复、调整 voicing 或乐句间隙，再考虑局部 EQ；不要为了让位把 bass 长期压低。频谱是候选遮蔽证据，不是听感结论。

## 5. 缺失或过低人声的排查

“人声听不到”先视为信号路径故障，不先加 Master 增益：

1. 在同一时间窗、同一增益/处理阶段比较 vocal stem 与对应源，考虑已知 item/take trim 和渲染电平差。
2. 查看 item/take gain、音量包络、track fader、静音、FX 顺序/旁通和路由；确认目标轨实际进入 master。
3. 只有在 stem 正常且轨道路径明确后，才确认实际 master 中人声的贡献。不要把 pre-master vocal stem 与 post-master accompaniment 直接比较；比较混合关系时应匹配处理阶段。
4. 先修 item、轨道、包络、FX 或路由。提高 Master 会连伴奏一起抬高并侵占峰值余量，不能作为静音人声修复。

### REAPER 音量包络 API

- 对 `VOLENV2` / `VOLTYPE 1`，宿主点值使用包络 scaling mode。受支持的更新接口应将 `Volume` 输入定义为线性增益，读取当前 `GetEnvelopeScalingMode` 后在内部转换，并在回执中返回实际 raw 点值和 scaling 信息。显式 raw 模式只用于调用者有意传入宿主刻度时。
- 部分旧版桥曾把线性 `Volume` 值直接传给 `InsertEnvelopePoint`，造成包络错误；这属于旧桥实现问题，不是通用宿主行为。若工具 schema/回执没有说明所用单位、raw 值和 scaling mode，不要猜值或继续写点；先按工具维护说明确认/重载更新后的服务。
- `points_added` 仅表示 API 添加了点，不证明有效音量正确。确认点值/scaling 回执，并仅对受影响片段比较 stem/source 或同阶段的 master 人声贡献。不可将总混非零或 peak 正常等同于人声存在。
- 明确故障修复后只做一次问题相关确认，不扩成全曲测试、反复交锁或规划审批。数值检查不是试听，也不证明人声自然、清楚或通过听感。

## 6. 总线、导出与来源

- Vocal Bus 只处理所有人声都共有的问题，避免逐轨强压后再次强压总线。
- 留出峰值余量。Limiter/饱和器是工具，不因插入或运行就代表母带/质量通过；没有发布目标时不强制套固定 LUFS。
- 人声、伴奏和 stems 统一起点。尾部由最后有效事件及真实效果衰减决定，旧静音 item 不应单独决定时长。Mono 干声复制为双通道不产生宽度；升采样或增加容器位深不恢复源精度。
- 若非宿主恢复链与 `.rpp` 不同，分别注明输入、处理来源和输出；不得称为该工程的原生可复现渲染。
- 只确认本轮规格要求的文件路径、格式、采样率、位深、声道、起点和长度一次。未试听应明确说明，不能根据谱图/测量写成听感通过。
